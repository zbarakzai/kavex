## The seam, changed

- `locate(term, label, limit)`: `limit` is the new `zaki.limit` label. `LIMIT` lives in `sessions.js` beside `LABEL`.
- A session keeps what `locate` said. If `found.limit` changes on the same session, `follow` stores it and bumps `changes`, so `numbers` runs again.
- `numbers(facts, session)`: the session is the second argument. Pi takes `limit` from it.
- `waiting` on the agent is the whole result: `{ state: "waiting", say }`. `dropdown.js` draws `say`. `WAITING` is gone from `sessions.js`. `first` carries `say` through the popup's props.
- `patience` on the agent, in ms: a `reports` agent with no label is `waiting` this long after first being seen, or as soon as it has worked. Codex has none, so only working counts. A live entry with no file holds `{ since, late, result }`.
- `tidy` clears both labels, and names only the ones set: Codex terminals still get `hc label t zaki.session=`.
- `context.used` can be `null`: Pi right after a compaction, or a session whose only answers failed. `{ used: null, total }`, no `percent`. `dropdown.js` draws `?` or `? / 200k`. Only Pi returns it.
- `numbers` may return a falsy value other than null (`false` from `facts.spent`). `read` only tests truth.

## Setup, for ticket 05

`pi.install({ home, read, write })` touches only `files`, never `herdr`, and writes one file: `<home>/.pi/agent/extensions/zaki-session.ts`. `setup: 1`. Parent folders may not exist, so `hc file write --on` needs them made if it doesn't (see 03).

The extension's `places` list follows `core_bin.rs`'s `usual_dirs`, as the Codex script does. Keep all three in step. It runs on the machine the Pi runs on, with that machine's `hc`, and `HC_TERMINAL_ID` there is that machine's bare address. Not tried.

Labels are read from the terminal record. A session file path in a label is the remote machine's. `watchFolder` is here only, so a remote Pi needs the 30-second poll like any other agent.

`SESSION_FILE` takes a Windows path (`C:\...`), and the extension is plain JS with no shell, so nothing about setup is Mac-only. Reading is still `sh`.

## Pi facts, from source (`@earendil-works/pi-coding-agent` and `pi-ai` 1.4.0, latest on npm on 2026-11-01)

**Approval: none for a global extension.** `addAutoDiscoveredResources` in `core/package-manager.js` adds user extensions outside both `if (projectTrusted)` blocks, and `docs/security.md` lists only project resources under trust. `/reload` re-discovers extensions and fires `session_start` with reason `reload`.

**Cost: API-style prices whatever the login.** Every provider stream calls `calculateCost(model, usage)` in `pi-ai/models.js`, which reads only `model.cost` from the catalogue (`providers/data/*.json`). Other facts:

## Reading

The filter is `"cacheRead":`, not `"totalTokens":`: Pi's fallback exists because older lines have no total. Escaped text can't match: `\"cacheRead\":` has a backslash before the closing quote.

Pi has no separate usage line: the whole answer, thinking and tool arguments included, is on it. So kept bytes are far higher than for Claude or Codex, and a line over 1 MiB that crosses a window edge is lost (parse fails twice). Answers are capped near 128k tokens, so that means an answer above about 250k tokens, or a tool result with `usage` and an image. Not handled: such a usage goes uncounted.

## Timing

`zaki check` on a debug binary, one 8 MiB window: 18,936 answer lines 190 ms, 25,891 `usage` lines 164 ms, `numbers` 0 ms. `shown` is constant time. Bun: a 100+ MB session with a 17 MB line reads whole, and after that at most 2.5 MB.

## Traps

- The guard refuses a bash line that sets `HOME`, and any `env ...` in a compound line. `zaki check` on a mod that only imports `pi.js` never reaches setup, so a scratch `HERDR_APP_HOME` is enough. Don't wrap it to get past the guard.
- Longer python heredocs are refused too: put edits in a script file.
- A real isolated core works with `HC_SESSION=x XDG_STATE_HOME=st` from a scratch folder. Stop it with both set: `hc server stop`.
