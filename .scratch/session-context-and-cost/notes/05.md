## The seam, changed

- `machineOn(on)` in `machine.js` is the one place that knows how machines differ. Null is this computer. A machine has `on`, `home`, `window` (blocks per read), `read`, `write`, `run`, `lines`, `sizes`, `inside`, `find`, `processes`. Nothing else in the mod imports `exec`, `readTextFile`, `home` or `writeTextFile`.
- Agents are handed the machine: `locate(term, label, limit, machine)`, `helpers(session, machine)`, `limit(model, machine)`. `install` gets the machine itself, as it already has `home`, `read`, `write`.
- `Sessions` has one pass per machine. `reading` is a Map of machine to `{ on, at, machine }`, and `still(run)` compares that object. `tick` starts this computer every 2 s and each added machine every 30 s, from `this.last`.
- `onMachine(on, name)` keys `agents.limits` and `agents.setup`: `vps/claude-opus-5-5`, `vps/codex`. This computer keeps the bare names, so nothing already set up runs again.
- `follows(t, all)`: on an added machine a terminal counts only with a row, meaning `agents()` or a parent chain reaching one. On this computer it's unchanged.
- `leftBehind(t)`: labels on a shell. A machine with only those still gets a pass, or a stale label would outlive its agent there.
- `lines(file, block, count, filter, known)`: `known` is a size already read in full; a file still that size prints only its size. Added machines only. It needs `done` on the entry in `session.files`, because a multi-window read sets `size` before it's finished.

## App and core facts (herdr-core source read as data, master and v0.1.15)

- **`hc file write` with no stdin exits 0 and writes an empty file.** Seen on an isolated core, 0 bytes, mode kept. `exec` and `hc()` have null stdin (`run_blocking`), so a mod calling it plainly would blank a person's `hooks.json`. The text must be piped, from a shell here.
- `hc file write` makes folders, follows symlinks to the target, keeps the mode, swaps atomically. Seen on the isolated core, without `--on`. It isn't compare-and-swap.
- `hc exec --json`: a missing program gives `{"error":{"kind":"spawn_failed","message":"cannot start X: ..."}}`, exit 1. A program failing gives `{"code":1,...}`, exit 0. Seen. `read_remote` relies on the same words.
- `run_remote` reads `hc exec --json` through `EXEC_OUTPUT`, 8 MiB, and stdout is base64 in that JSON. So over about 6 MiB of output the JSON is cut, parsing fails, and exec rejects. Hence 4-block windows on added machines. A Pi session could never have finished at 8.
- `exec.rs`: at most 16 running per core, `MAX_STDOUT` 8 MiB. Passes are serial per machine.
- `remote.rs` and `schema/README.md`: a machine's terminals stay in the stream while its line is down, and arrive again on reconnect (`mirror_replace`). A lost line fails calls at once ("lost the line"). A stuck one takes up to the deadline.
- `machines()` says `unavailable` for offline, and also for connected with a failed layout read (`Slot::layout`). Reading pauses for both.
- `machine add` installs `~/.local/bin/herdr-core` with `hc` linked beside it only if there's no `hc` on PATH. Windows: `%LOCALAPPDATA%\Programs\herdr-core\herdr-core.exe` with `hc.exe` hard linked, same rule. So the hook's folders are right, but an unrelated `hc` first on PATH (window managers ship one) stops the loop at it: no label, `–`, never a wrong number.
- **Windows foreground:** `platform/windows.rs` `foreground()` returns `self.pid`, "No process groups on a pseudo console: the program it started". So for an agent started in a shell, `foreground.pid` is the shell. Claude's record is never there.

## Windows filter, and why

- Official docs read 2026-11-01: `findstr` (learn.microsoft.com, windows-commands) has no way to start at an offset; `/o` only prints one. `Select-String` for 5.1 is line-based, decodes with `Default` (the active code page), matches with the current culture, and has no offset.
- Neither can do windows, and whole-file output runs into exec's 8 MiB, where it's cut with no error. Lost lines mean an understated number, which is the failure the ticket forbids.
- So: `FileStream` through `[IO.File]::Open` with `FileShare` `ReadWrite, Delete` (the agent is writing it), `Seek`, one window, Latin-1 code page 28591 so a byte is one character and `$hit.Index` is a byte offset, `[regex]::Matches` on the escaped needles, and the matching byte ranges written raw to stdout. Same contract as `dd | grep`: size, then lines in file order.
- `powershell` is 5.1 everywhere it exists. Pattern taken from `files/ops.js`: `-Command "& { param(...) ... } 'a' 'b'"`. `-EncodedCommand` was left out: it's the classic pattern security tools flag.
- `about_Quoting_Rules` confirms smart quotes are quotes: `single` doubles all four kinds. `ops.js`'s `single` doubles only `'`. A path with `’` breaks there. Not changed: out of scope, worth a ticket.
- Exit 3 is no file; anything else nonzero throws, however much it printed. `take` on Mac and Linux doesn't check the code, because `grep` exits 1 on no match.
- **Never run. No timing.** Estimate only: 0.3 s startup plus the scan per window, so a first read of 100 MB is several seconds off the main thread.

## Test helpers, new

`addMachine(name, more)` gives a home in the scratch; `more` takes `offline`, `stuck` (a promise), `windows`, `gitSh`. `claudeThere`, `codexThere`, `thereHooks`, `goesOffline`, `onWindows(home)`, `claudeOnWindows`, `noShell`, `walks`, `inWindows`, `WINDOWS_CWD`. `known(draw, address)`. Path helpers take `at`. `state.onRead(path)`, `state.powershell(script)` (return a result, or null to carry on), `state.noPowershell`, `state.noWindow`, `state.fed`, `state.execOn`, `state.readOn`, `state.platform`.

`fakeBin` puts a stand-in `hc` first on PATH for every `exec`, so no test can reach a real one, and it refuses paths outside the scratch.

`powershellCall(command)` tokenises the command by PowerShell's rules and throws if anything after the script isn't a string. `powershell()` and `windowsExec()` recognise scripts by text and answer what they should print. **Nothing PowerShell runs here, so these test the mod, not the scripts.**

## Traps

- The guard refuses `hc machine add --via 'sh -c'` ("cannot be shown not to be git"). Not reworded. A heredoc with `cd`, and `cd` with a compound line, are refused too: use Write and Edit, and plain commands.
- A `gh` loop is refused; one plain `gh api -H 'Accept: application/vnd.github.raw' ... > file` per file works.
- `sed -i` on a line with `‘` in it: my first two patterns silently matched nothing, and the tests "passed" a mutation that never happened. Check `git diff --stat` printed something.
- A mutation that doesn't reach the code proves nothing either: `const here = all` left the stuck test passing because a remote terminal was read with the local machine. Sharing one `reading` key was the right break, and it needed the test to change a local file while stuck.
- `/bin/dash` exists on this Mac: a real check of the read script's syntax for Linux, with BSD tools.
