## The seam, changed

An agent can now also have:

- `reports: true`: it says its own session through the `zaki.session` label. With no session reported, `sessions.js` gives it `empty`, or `waiting` once its terminal has been seen `working` or `done` (see below). Pi needs this too. Check it reads right for Pi: Pi's extension runs at launch, so for Pi "no label" may mean `waiting` sooner than "has worked".
- `locate(term, label)`: the label is now passed in. `LABEL` lives in `sessions.js`.
- `setup` (a number) and `install(files)`: see Setup.
- `numbers` may return `context: { used, total, percent }` itself: `shown()` then passes it through and `ask()` is skipped. An agent with no `limit` must do this. Pi: total from its label, so `numbers` needs that label; `add`/`numbers` don't get the terminal, so pass it through `locate`'s result into the session, or read it in `follow`.
- `add(facts, line, helper, file)`: `file` is new, for per-file state. Windows re-read lines, and helpers interleave with the main file between reads, so anything like "the current model" must be per file.
- `filter` may hold several fixed strings, one per line: grep `-F` takes that (BSD here; GNU by POSIX, not run).
- `read` now lists helpers until no new file turns up, so nested helpers arrive in one read. `s.files.has(path)` in `watch` wakes a session for a helper whose path doesn't hold its id.
- `sizes(stdout)` in `sizes.js` parses `wc -c` for any agent.
- `dropdown.js` draws `waiting`. Its message names Codex, so **Pi needs its own wording** if it can ever be `waiting`: make the text come from the agent or the state.
- `drawDropdown` keeps `first` when the copy says `empty` and the row said `waiting`: a dropdown copy can't know the agent worked before it opened.

## Setup, for tickets 04 and 05

`Sessions.setUp(name, agent, cx)` runs `agent.install({ home, read, write })` from the list copy, once per `agent.setup` per `name`, recorded in `shared("agents.setup")`. A false or failed install retries after 10 minutes, per `Sessions` instance.

- Ticket 05: `name` is the key, so make it per machine (`vps/codex`), and pass `files` built on `readTextFile(path, { on })` and `hc file write --on`. `install` only touches `files`, never `herdr`. `home` must be that machine's: get it there, not from `home()`.
- `write(path, text, expected)` is the app's rule: `expected` null means it must not exist. It makes parent folders here. **`hc file write --on` may not: check.** It's also not compare-and-swap, so a race can lose a person's edit: read just before.
- Ticket 04: add `setup` and `install` to Pi; the list copy's call site is already generic.
- Zaki's own files go in `~/.zaki/`, not `appHome()`. `appHome()` moves with `HERDR_APP_HOME` and `XDG_CONFIG_HOME`, so `just dev` would add a second hook and ask for a second approval. Added machines have no app home anyway.
- `just dev` shares the real `HOME`, so a dev window that sees a Codex **really writes `~/.codex/hooks.json`**, and sessions tests can't catch that. Use a scratch `HOME` for dev windows.
- The test fake's `writeTextFile` refuses paths outside the scratch home, and `exec` runs with `HOME` scratch. Keep both.
- Windows: `install` runs there today and adds the hook, but reading needs `sh`, so such a row shows nothing wrong, only no numbers. The `.ps1` was never run: no `pwsh` on this Mac. Its `commandWindows` is in the hook now because Codex hashes only the platform's command, so it can still change without Mac users re-approving, but Windows users would.

## Codex hook, from its source (`codex-rs`, main, read 2026-11-01)

- **SessionStart runs at the first turn, not at launch.** `session_init` queues a pending source for every new session, `run_turn` runs it, and it runs mid-turn after an auto-compact too. So before the first message there is no label, for approved and unapproved alike.
- Sources: `New` startup, `Cleared` clear, `Resumed` resume, `Forked` fork, and compaction queues compact.
- Subagents: thread-spawned ones run `SubagentStart` instead, other subagents run nothing, so a helper can't relabel its parent.
- Trust: the key is `<hooks.json path>:session_start:<group>:<hook>`, in `config.toml` under `[hooks.state."..."]` with `trusted_hash`. The hash covers event, matcher, the platform's command, timeout, async, status message. Nothing reads the script. `command_windows` is cleared before hashing.
- Run by `$SHELL -lc <command>` (`/bin/sh` if unset), env inherited on Unix, in a new session, so not the foreground group. Stdout goes back to Codex (the docs say it becomes context), so hooks must print nothing. **Real `hc label` prints JSON**, and the script discards it.
- A bad `hooks.json`: a warning, that file's hooks skipped, others still load.
- `/new` with no arguments opens a checkout picker first; `/clear` is `AppEvent::ClearUi`. Neither was followed to the thread start; the case for `/new` is that the queueing is unconditional.
- This Mac: `[features] hooks = true` is set by hand in `config.toml`. Whether a person without it gets hooks at all wasn't checked. `CODEX_HOME` isn't honoured: Zaki writes `~/.codex/hooks.json`, and `exec`'s env wouldn't have it after a Dock launch anyway. Such a person stays at `–`.
- `settings.json`'s `core` isn't known to the hook: an `hc` only there isn't found. The script follows `core_bin.rs`'s `usual_dirs`; keep them in step.

## Facts on real Codex files (402 session files, 1.6 GB, `cli_version` 0.144 to 0.166)

- Every line: `timestamp, ordinal, type, payload`. `ordinal` rises by line, but one file repeats one. Not used.
- `event_msg` / `token_count`: `info{ total_token_usage, last_token_usage, model_context_window }`, `rate_limits`. `info` can be null (5). Usage: `input_tokens` (holds cached), `cached_input_tokens`, `cache_write_input_tokens` (0 on every one of 39,509), `output_tokens` (holds reasoning), `reasoning_output_tokens`, `total_tokens`.
- `model_context_window` is 95% of the model's: 258400, 353400, 475000.
- Repeats: 948 records repeat the total. **Totals fall back to about zero 5 times in 4 files**, mid-turn, with `last` still right, so the newest total loses cost. `delta == last` for every other record (38,160).
- **After `compacted`**, a record has the same total, input and output 0, and only `total_tokens` set to the new size (283 records). Context drops at once and it costs nothing. Codex's own percent reads it too.
- `token_usage_record` lines (newer versions) repeat per-response usage; not used.
- `turn_context`: `model` per turn. 9 files changed model. `event_msg`/`thread_settings_applied`: `thread_settings.service_tier`, always `"default"` here, absent on 130 of 1,079. `ServiceTier` serialises `fast` and `flex`; `priority` is the request value. No real `fast` line was seen.
- `long` prices: `last.input_tokens` over 272K on 351 of 39,509 records.
- Helpers: `session_meta.parent_thread_id` and `source.subagent.thread_spawn{parent_thread_id, depth}`, in the first line at offset under 350. `forked_from_id` was set on 180, all with a parent: **no `/fork` of a person's session exists on this Mac**, so whether a fork's file copies token records is unknown. Helper forks don't copy them. 51 files have a second `session_meta` (the parent's), so never trust "first meta wins" past line 1.
- Depth reaches 3. 39 of 238 helpers are in another day's folder, so watch and search the whole `sessions` root. `SubAgentActivity` items (`kind` started, interacted, completed, interrupted; `agent_thread_id`) name 234 of 238. The other 4 are old (July, 019f ids), have no `turn_context`, and go uncounted: one 91.6 MB session reads $48.72 where the truth is "no price". A live session won't be on that format.
- The filter keeps 42 of 1,617 MB, at most 2 MB of a file. Biggest kept line 7.8 KB, biggest of any kind 17.6 MB (`compacted`).
- Real `terminals()` status words come from `herdr.d.ts`; `hc` 0.1.15 `get --json` has `labels`, and `foreground: null` for a non-agent.

## Traps

- A check in this repo that uses a fake `hc` proves nothing about stdout, unless the fake prints what real `hc` prints.
- The fixed `hc` folders in the script mean a test can reach a real `hc`: two tests skip where one exists.
- Reads of `exec` can't see the app's `core` setting.
- A real isolated core works from the worktree with `env -i HOME=<scratch> PATH=/usr/bin:/bin HC_SESSION=x XDG_STATE_HOME=<relative>`: a relative state folder keeps the socket path short.
- The guard refuses a bash line with a pipe into a loop or `$(...)` in a tool's arguments. Put it in a script file.
