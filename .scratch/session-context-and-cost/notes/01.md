# Ticket 01 notes for tickets 02 to 05

Branch `session/01-claude`. Files: `defaults/mods/agents/sessions.js` (timing, reading, limits), `claude.js` (the one agent so far), `dropdown.js` (drawing only), `scripts/sessions.test.ts`.

## The seam

Add an agent to `AGENTS` in `sessions.js`, keyed by `program.key`. An agent is an object:

- `locate(term)`: `{ id, folder, file }`, or null. Null keeps the last session.
- `filter`: a fixed string for `grep -F`.
- `facts()`: a fresh running state.
- `add(facts, parsedLine)`: must be idempotent, because lines are read twice (see Reading).
- `numbers(facts)`: `{ model, asked, used, tokens }`, or null for `empty`. `asked` is what to pass to `limit`.
- `limit(model)`: a total, or null. Optional thinking for Codex and Pi: their totals are in the session or a label, so `ask()` and `shown()` will need a way past `shared("agents.limits")`.

`shown(address)` returns the spec's shape. `state: "waiting"` isn't drawn yet: `percent()` in `main.js` and `dropdown.js` need it for ticket 03. Cost goes in `add` and `numbers`, and the dropdown's line in `dropdown.js`.

`hasSession(t)` in `sessions.js` excludes addresses with a `/`. Ticket 05 lifts that, and must thread `on` through `exec`, `readTextFile` and `limit`. `watchFolder` and `readTextFile`'s home are here only.

## Facts on real Claude files (version 2.1.316)

- `~/.claude/sessions/<pid>.json`: `pid, sessionId, cwd, startedAt, procStart, version, kind, entrypoint, status, updatedAt, name, ...`. 10 of 10 records with a file derived their path as `projects/<cwd with every non-alphanumeric as ->/<sessionId>.jsonl`. Claude may shorten very long folder names: not handled, and it would read as `empty`.
- Key order of an assistant line: `parentUuid, isSidechain, message{model, id, type, role, content, ..., usage{...}}, ..., requestedModel, type, uuid, timestamp, ...`. Never rely on it: lines are JSON-parsed whole.
- `usage`: `input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens, cache_creation{ephemeral_1h_input_tokens, ephemeral_5m_input_tokens}, service_tier, speed, iterations[...]`. The 5m and 1h split is there for ticket 02. `iterations` repeats the numbers.
- Repeated lines: 1 to 5 per message id, and usage never differed in about 24,000 lines across 120 files.
- `model: "<synthetic>"` lines have zero usage (77 seen). Skip them.
- Helpers are in `<sessionId>/subagents/agent-*.jsonl` with `.meta.json` beside them. No `isSidechain: true` in the main file in the 120 newest, but the check stays for old files.
- Ticket 02: **tokens here leave helpers out.** Spec says totals cover them, and that came in with its cost story. The folder watch is recursive and `path.includes(id)` already marks helper changes, so only the read needs adding. `cached` is read plus write.
- `toolUseResult.usage` in `user` lines holds a helper's usage. `line.type === "assistant"` keeps it out.
- A 107 MB session: 1,312 usage lines, 4.3 MB of them, biggest assistant line 49 KB, biggest line of any kind 1.4 MB.
- `compact_boundary` system lines have `compactMetadata{trigger, preTokens, postTokens, ...}`. Not used.
- `/context` reply: JSON with `result` holding `**Tokens:** 13.7k / 1m (1%)`, `local_command: "context"`, `total_cost_usd: 0`.
- `claude -p` warns after 3 s of open stdin. `exec` has null stdin, so that won't apply.

## Reading

- `sh` script: `wc -c` then `dd bs=1M skip=N count=8 | LC_ALL=C grep -aF`. Exit 3 means no file. Never `head -c`: BSD's is five times slower.
- `exec` silently cuts stdout at 8 MiB, so 8 MiB windows can't overflow it. Each window starts a block back. After a full read only the last 1 to 2 MiB is read.
- Ticket 05: `dd`, `wc`, `grep` have no Windows counterpart yet. `sessions.js` keeps the script in one constant for that.
- `session.changes` / `session.done`: a session stays due until a read reaches the end. `this.reading` is also the pass's token: a replaced pass must not touch state, and any new awaits in `read` or `follow` need the same check. This was a real bug found on real files (see the ticket).
- `agents.limits` in `shared` is keyed by model alone. Ticket 05 needs a machine in the key.

## App facts

- `terminals()` has `foreground` (real, seen live). `hc ls --json` is a summary without it. `hc get <t> --json` has it.
- A dropdown copy has its own `Sessions`, reads from the start (1.3 s on 107 MB) and draws `props().first` until then. It runs no `/context`: only the list does, and `setShared` reaches every copy.
- Props hash to a store file name, but a dropdown never writes one.
- `watchFolder` has one queue per folder: all waiters get a batch, but a call finding `pending` takes it alone. So a list and a dropdown can rarely miss a change; the next one heals it.
- Popups fit their content; `height` is a limit.

## Dev window traps

- Socket paths are limited to 103 bytes, and the scratchpad is too long for both `XDG_STATE_HOME` and `HERDR_APP_HOME`: both need a short symlink (I used `/tmp/zs01`, `/tmp/zs01h`, removed since). Without it the window opens but `zaki do` and `zaki shot` can't reach it.
- Override `HOME` with a scratch home and fake records: a sleeping process in a terminal plus OSC 7501 `app=claude` makes a row with no real Claude. Set `settings.json` `core`, since the login PATH is gone with `HOME`.
- `hc ls` has no foreground: use `hc get`.
- Fixture lines written from Python need `separators=(",", ":")`, or the filter misses them.
- Run `zaki` with `PATH` holding `hc`.
- A hot copy made after start moves to `agents-edited` only on restart. Delete it.
- Compare `zaki shot` against `bench.jsonl`'s `scripts` count: 0 means the window isn't drawing and the shot is stale.
- A huge time gap in `bench.jsonl` means the machine slept. Timings in wake bursts aren't reliable.
- On this Mac the shell's `grep` is ugrep: use `/usr/bin/grep` for anything measured.
