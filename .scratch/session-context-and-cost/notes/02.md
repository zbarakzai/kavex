# Ticket 02 notes for tickets 03 to 05

Branch `session/02-cost`. New file `defaults/mods/agents/prices.js`. Read `01.md` first; this says what changed.

## The seam, changed

An agent can now also have:

- `helpers(session)`: optional, `[{ file, size }]`. Files read with the session; one whose `size` matches what was last read is skipped. Claude's is one `wc -c` over `<folder>/<id>/subagents/*.jsonl`. Codex's will be its parent-id search. Leave `size` out to read every time. It runs through `exec`, so it needs a Windows way in ticket 05.
- `add(facts, line, helper)`: `helper` is true for a helper's file. Lines of one file don't say which file they're from, so an agent needing per-file state (Codex's newest record per helper) needs `add` to get the file: small change to `take` in `sessions.js`.
- `numbers(facts)` now returns `cost`: a number, or `undefined` for "no price". `dropdown.js` draws it, and draws any number it gets.

`read` is now `read` plus `take(session, file, agent, run, helper)`. `session.block` became `session.files`, a Map of file to `{ block, size }`. A file found shorter resets the facts and clears the Map, and `read` starts over. `still(run)` is the replaced-pass check: any new await in `read` or `take` needs it.

## Prices, for ticket 03

- Add entries to `PRICES`: exact model id to rates by class, in dollars per million. `priced(rates, tokens)` sums whatever classes it's given and returns null if a class with tokens has no rate. So OpenAI needs `{ input, read, output }`, with its token object named the same. Take cached out of input first (spec).
- `priced` is per call, so Codex can price per model or per record, but not a single total over several models.
- Add a line to the header of `prices.js` with the OpenAI page and the date read. Page first, never memory.
- `prices.js` is on the list the no-network test scans, which bans `https?:`. Write page addresses with no scheme.
- `REGIONS`, `fast` and `over` are Claude's. `dollars` in `claude.js` applies them, not `priced`. A Codex model with a tier or fast price needs the same in its own agent.
- Pi: no list. Sum `usage.cost.total` in `add` and return it as `cost`. The sum must count each message once, and if a Pi file repeats lines the same way, keep the biggest.

The line "What this would cost on the API, not what you paid." is drawn for every `ready` session. The spec drops it for Pi if Pi's cost is at API prices, so ticket 04 needs a field for that. Not built.

## Running totals

`numbers` must stay constant time: it runs in the same step as a window's parse, on every read. It first summed every message, which was 201 ms at 50k messages. So `add` keeps totals, and `facts.messages` holds only what each message added. Do the same for any agent.

## Test helpers, new

`card(draw)` is now the way to read a dropdown: it opens one and asserts it agrees with `known(draw)`, which is what the list has worked out. A dropdown copy reads from scratch, so on its own it can't see a bug in the list's following. `known` alone is for cases where they rightly differ (a helper file that went away).

`changed(path)` wakes every watcher, as `watchFolder` does. `state.watchers.shift()` wakes one, and with a dropdown open that may not be the list's. `changes` and `helperChanges` use `changed`, so an open dropdown does its own read: expect double counts.

`realReads()` counts reads, not listings. `helperOf`, `helps`, `helperChanges` for helpers. `said` gained `write5m`, `speed`, `geo`; its `write` is 1-hour. `state.listing` holds the listing's `exec`. `state.home` moves the home folder.

## Timing in the real runtime

Bun's JIT says nothing about the budgets. `zaki check` runs QuickJS with no window, and a thrown `Error` carries results out. An `init` is one step, so one scenario per check, or the harness itself prints `interrupted`. Build fixtures with `.replace` on one line: `JSON.stringify` per line eats the budget. Set `HERDR_APP_HOME` to a scratch folder and copy the mod outside `defaults/`, which `build.rs` embeds.

`add` costs about 5 µs a line plus `JSON.parse`. The smallest real lines are the worst: 155 ms for a 6.3 MiB window.
